# 进程：程序的一次运行，不是一份文件

## 异常不只有“出错”

CPU 正常沿指令流执行，但外部中断、系统调用、缺页和非法指令都可能让控制转入内核。中断通常异步出现；陷阱常用于有意请求服务；故障有些可以修复后重试，比如合法页面尚未驻留；不可恢复的严重情况则终止。课程的分类与具体体系结构术语要对照，不要把所有异常都叫崩溃。

进程提供两种重要感觉：好像独占 CPU，好像独占内存。实际由调度切换和虚拟内存实现。程序是磁盘上的代码与数据；进程还包括运行中的寄存器、地址空间、文件描述符等状态。

## fork 为什么“一次调用，两个返回”

调用前只有父进程；成功 fork 后父子都从调用后的语句继续。父进程得到子 PID，子进程得到 0；失败只在父进程返回 -1，没有子进程。子进程看起来得到独立地址空间，常通过写时复制实现；之后普通局部变量各自修改，不会自动互相通信。

```c
int x = 10;
pid_t pid = fork();
if (pid == 0) { ++x; printf("child %d\n", x); }
else if (pid > 0) { printf("parent %d\n", x); }
```

成功时分别输出 11 和 10，但先后顺序不固定。不要因为代码先写 child 分支就断定子先运行。标准输出缓冲区也会被复制：fork 前未刷新的数据可能被双方再次刷新，造成看似多打印一次。

## exec、exit、wait 各做一件事

exec 系列用新程序替换当前进程映像，成功时不返回；不是再造一个进程，因此 PID 通常保持。exit 结束进程并执行库层清理，`_exit` 跳过用户态 stdio 等清理；两者使用场合不同。父进程用 wait/waitpid 回收子进程退出状态；只退出但未回收的子进程可能处于僵尸状态。

## 画树再数输出

连续两次 fork 且全部成功、每个进程都执行两次时，数量从 1→2→4。若某个分支提前 exit，或只让父进程第二次 fork，就不能套 $2^n$。逐次画出“谁会执行下一行”，比凭经验猜更稳。

**自测。** exec 成功后会执行它后面的 `printf("done")` 吗？答：不会；当前程序已被替换。只有 exec 失败返回，才可能走到后面的错误处理。
