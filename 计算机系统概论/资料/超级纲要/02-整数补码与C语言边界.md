# 整数：同一串位，为什么能有两个答案

## 先用四个位算一遍

无符号四位数的权重是 8、4、2、1，所以 `1101` 是 $8+4+1=13$。补码把最左位的权重改成 -8，后面不变，所以同一串位是 $-8+4+1=-3$。一般地，$w$ 位补码取值为

$$x=-b_{w-1}2^{w-1}+\sum_{i=0}^{w-2}b_i2^i.$$

无符号范围是 $0$ 到 $2^w-1$；补码范围是 $-2^{w-1}$ 到 $2^{w-1}-1$。负数多一个，是因为零占去了非负半区的一个位置。`1000` 是 -8，它的正数 +8 在四位有符号数里放不下。

## 为什么“取反加一”能取相反数

四位加法硬件只保留低四位，效果是模 16。3 的位串为 `0011`，逐位取反为 `1100`，加一为 `1101`。两者相加是 `1 0000`，丢掉最高进位后为 0。所以 `1101` 正好充当 3 的加法逆元。注意：对最小补码取反加一会得到它自己；这是位运算事实，不是说数学上 $-(-8)=-8$。

## 两种溢出，要看两种标志

四位 `1111+0001=1 0000`：无符号 15+1 超出范围；按有符号解释则是 -1+1=0，并没有有符号溢出。四位 `0111+0001=1000`：无最高进位，但有符号 7+1 超出范围，显示成 -8。无符号看最高进位，有符号看同号相加却得到异号。CF 和 OF 分别服务这两件事。

C 中无符号运算按模 $2^w$ 定义。有符号溢出属于未定义行为：编译器可以假设它不会发生。因此不要用 `x+1<x` 这种有符号表达式检测溢出；应在加法前比较 `x > INT_MAX-y` 等边界，并按符号分情况处理。

## 转型：先问值，再问位

把 -1 转成 `unsigned int`，结果是该类型的最大值。混合比较 `-1 < 1u` 时，常见平台会先把 -1 转成 unsigned，比较于是为假。这里失败的不是数学比较，而是参与比较的类型已经变了。

扩宽无符号数通常补零；扩宽有符号补码通常复制符号位。截断只留低位会丢信息。但具体超范围的有符号转换要按所用语言标准和实现判断，别用一条“所有强转只改标签”概括。

## 右移不等于所有整数除法

对无符号数右移 $k$ 位等价于除以 $2^k$ 向下取整。C 的有符号整数除法向零截断：$-7/2=-3$。算术右移 -7 常给 -4，二者差 1。若平台采用算术右移，对负数加偏置 $2^k-1$ 后再移位可实现向零截断，但移位宽度必须合法，且要避免中间溢出。以 -7 为例，$(-7+1)\gg1=-3$。

**易错点。** `1 << 31` 不是在所有 C 环境下都安全；表达式先按 `int` 算，最后赋给 64 位变量也救不了前面的溢出。要构造无符号掩码，应从足够宽的无符号 1 开始，并保证移位量小于位宽。

**自测。** 八位 `10000000` 作为补码和无符号分别多少？答：-128 与 128。为什么不能用八位补码保存 128？因为最大正数只有 127。
