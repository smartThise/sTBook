# 输入输出：一次 read 不保证读完你要的东西

## 文件描述符是一个小整数句柄

open 返回文件描述符，read/write 用它请求内核操作。进程的描述符表指向内核的打开文件状态，再指向文件等对象。fork 后父子对应描述符可能共享打开文件描述的偏移；dup 也会让两个描述符指向同一个打开文件描述。两个独立 open 则通常有各自偏移。

因此“两个 fd 数字不同”不保证读写位置独立；“两个进程”也不保证偏移独立。反过来，同一个 fd 数字在不同进程中完全可以指向不同对象。

## 短读、短写是正常情况

`read(fd, buf, n)` 返回实际读取字节数，可能小于 n。返回 0 表示该次读取遇到 EOF；返回 -1 表示错误，要检查 errno。管道、终端、网络和信号中断都可能让一次调用无法完成整个逻辑消息。

可靠读写循环应维护“已完成量”和“剩余量”，每成功一次就移动指针；对 EINTR 按接口语义处理；遇到 EOF 时把“完整消息”“提前结束”区分开。不能因为暂时只来了 20 字节，就当后面的 80 字节永远不存在。

```text
done = 0
while done < need:
    n = read(fd, buffer + done, need - done)
    if n > 0: done += n
    else if n == 0: return 提前EOF(done)
    else if errno == EINTR: continue
    else: return 错误
return 完成(done)
```

这里的 read 是阻塞式简化模型。非阻塞 fd 遇到 EAGAIN 需要等待就绪等机制，不能不加限制地死循环重试。

## stdio 缓冲和内核不是一层

printf/fread 等库接口可以先把数据留在用户态缓冲区，减少系统调用次数；write 直接进入内核接口。混用时要留意刷新顺序，fork 时也要留意复制缓冲。写进内核缓存不一定已经落到持久介质，fflush 与 fsync 的职责不同。

重定向的核心是让标准输入/输出描述符指向其他打开对象，常用 dup2。打开标志、文件元数据查询和目录操作也都围绕“句柄指向什么对象、对象具有什么状态”来理解。

**自测。** read 返回 7，而你请求 100，是否是报错？答：不是；7 是成功读到的数量。只有返回 -1 才进入错误检查。
