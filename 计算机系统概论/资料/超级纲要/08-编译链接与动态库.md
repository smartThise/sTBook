# 链接：把分散的代码接成能运行的程序

## 一份源文件并不是整个程序

预处理展开头文件和宏；编译把 C 翻译为汇编；汇编生成可重定位目标文件；链接器把多个目标文件和库组合起来。`.o` 里通常还不知道其他文件的函数最终放在哪，所以既保存机器码，也保存“这里以后要填地址”的记录。

符号表回答“这个名字在哪个节、哪个位置”；重定位记录回答“哪处指令或数据需要按符号地址修正”。同一名字的局部变量不一定参与链接；函数内自动局部变量多数存在栈或寄存器中，而文件作用域变量与函数通常需要链接器处理。

## 先分清三种 static

文件作用域 `static int x` 限制为本翻译单元内部链接；函数内 `static int x` 具有静态存储期，跨调用保留值，但不是普通栈变量；C++ 类的 static 成员又涉及类语义。它们共享词形，不表示同一个机制。`extern int x;` 通常是声明，不分配一份新的普通定义。

旧教材的“强符号/弱符号”讲法依赖工具链策略。现代 GCC 默认 `-fno-common`，多个翻译单元重复写 `int x;` 可能直接报多重定义；不能把旧版 common 合并规则当 C 语言允许重复定义的保证。可靠做法是一个地方定义，其余头文件声明。

## 一个最小重定位例子

文件 a.c 调用 `f()`，b.c 定义 f。编译 a.c 时先留占位，链接后才知道 f 的相对位置。若调用指令采用 PC 相对位移，逻辑上需要计算

$$\text{位移}=\text{目标地址}-\text{下一条指令地址}.$$

具体 ELF 重定位项还涉及 S、A、P 的定义，不能把“下一条地址”与重定位字段地址混为一谈。解题时先写清楚字段位置、指令长度和所用重定位类型，再代数。

## 静态库的顺序为什么重要

传统静态库按命令行从左往右扫描，为当前未解决的引用提取成员。因此常写 `main.o -lfoo`，先产生对 foo 的需求，再去库里找。循环依赖可能需要分组扫描或调整结构。库里没被引用的对象不一定全塞进最终文件。

动态库让代码在装载或运行时共享。GOT 保存间接地址，PLT 常用作函数调用跳板；惰性绑定是在第一次调用时解析，但系统也可以配置立即绑定。PIC 通过位置无关的访问方式支持装载到不同地址，不能简单理解为“程序里再也没有地址”。

**自测。** 两个源文件都包含同一个头文件，头文件中写了普通全局变量定义，为什么可能失败？答：包含是文本展开，两边各产生定义；应把定义放进一个源文件，在头文件里写 extern 声明。
