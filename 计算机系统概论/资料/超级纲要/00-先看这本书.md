# 从一行 C 代码开始，看懂计算机在忙什么

你写下 `int x = 1; x += 2;`，电脑给出 3。前一门程序设计课可能已经教过这种代码。计算机系统概论接着问：1 放在哪里？加法由谁执行？为什么同样的加法，有时会得到负数？程序明明没有写“同时执行”，为什么窗口、播放器和终端还能一起动？

这些问题都能落到具体状态上。内存某个地址有几个字节，寄存器里有哪个位串，下一条指令是哪条，操作系统允许哪个线程继续执行。读本书时，手边留一张纸。遇到程序，就画几个格子，把格子里的值随执行过程改掉。许多“玄学错误”只是某个格子比你想象中早改了，或者根本没有改。

## 先认识四个每天会见面的东西

CPU 是执行机器指令的处理器。机器指令是处理器能识别的操作，例如把一个数从内存读进寄存器，把两个寄存器相加，或者转到另一个指令地址。寄存器是 CPU 内部少量、可直接操作的存储位置。本书中的 `%rax`、`%rdi` 都是寄存器名字。

内存可以先想成一排按字节编号的格子。地址是格子的编号，内容是格子里装的位串。“地址 100 的内容是 7”含有两个数：100 用来找位置，7 才是读到的数据。后面的大量指针题，都在检查你有没有把位置和内容混为一谈。

操作系统管理运行中的程序和硬件资源。一个正在执行、带着地址空间和资源的程序实例叫进程。一个进程中可以有多个线程；线程各自保存“执行到哪里”和自己的栈，但可以使用同一进程的许多数据。

编译器把符合 C 规则的源代码转换成目标机器代码。链接器把不同文件里定义和使用的函数、变量连接起来。你敲下一个编译命令时，工具链往往替你依次做了预处理、编译、汇编、链接四项工作。它们在第 08 章拆开讲。

## 用三个小问题确定阅读起点

第一题：`int a[3] = {10,20,30};`，假设每个 `int` 占 4 字节，`a` 从地址 `0x1000` 开始，`a[2]` 在哪里？数组下标从 0 开始，因此跳过前两个元素，共跳过 `2×4=8` 字节，得到 `0x1008`。如果你答成 `0x1002`，先看第 01、07 章；你缺的是“下标乘元素大小”这一步。

第二题：一个 8 位补码位串 `11111111` 表示什么？最高位的权是 −128，其余七位合计 127，因此是 −1。同一位串当无符号数读则是 255。若这看起来像“电脑随便改答案”，先看第 02 章；读法由类型和规则确定，并不随意。

第三题：两个线程各做一次 `counter++`，结果一定加 2 吗？在普通共享非原子变量上，这种写法在 C 里存在数据竞争，程序没有标准保证；把它拆成读、加、写，还能画出两个线程都读到旧值、最后只留下加 1 的过程。若你没有接触线程，可以先跳过；读到第 14 章时再回来画状态表。

## 怎么用每一章

每章先交代一个实际问题，再介绍解决它所需的名词。算例会写出中间状态。你第一次读时可以跟着算；第二次读时遮住答案，只看题意，自己重画地址、寄存器或时间顺序。两种读法带来的感觉不同：看懂别人怎么算，比自己从空白纸算出来容易得多。

练习答案紧跟在题后，方便即时核对。不要只核对最后一个数。假如最终数一样，但你把小端顺序反过来又误用另一条公式，两个错误可能刚好抵消。应检查每一步使用的位宽、数据类型、地址单位和执行顺序。

遇到不认识的名词，可以把问题写得具体一点：“这里说的页，是磁盘上的块还是地址空间的一段？”“这个锁现在由哪个线程持有？”“这一位为什么补 1？”这种问题能直接指出下一段需要补的知识。单纯觉得“好抽象”时，也可以先找出句子里第一个不能画出来的名词。

## 本书采用什么机器与规则

机器表示和汇编主线使用教师课件中的 x86-64、AT&T 语法。多数例题采用 Linux 上的 System V AMD64 调用约定，以及常见 LP64 数据模型：`char` 1 字节、`short` 2 字节、`int` 4 字节、`long` 和指针 8 字节。这里的“常见”是环境假设，不能拿去断言所有 C 实现。Windows x64 的 `long` 通常为 4 字节，调用约定也不同；苹果芯片的本机指令是 ARM64，不能直接运行书中的 x86-64 汇编。

C 语言边界主要按 C17 讨论。无符号算术按模运算，普通有符号溢出属于未定义行为；负有符号数右移在这个版本的 C 里由实现规定。书中若模拟“截断后的位串”，会明确那是固定宽度机器算术，不能把它冒充 C 对所有表达式的承诺。汇编例子中的地址是便于手算的假地址，不是你电脑上的实际地址。

## 常见词放在同一套关系里理解

位串是一组0和1，值是按某种规则从位串读出的含义，类型规定程序允许怎样解释与操作。地址是位置编号，指针是能保存某类对象地址并按规则操作的值。对象是有类型、大小和生命周期的一块程序数据。读到“地址里的值”时，先问对象是什么类型，才知道读几个字节、怎样解码。

指令地址告诉处理器去哪里取下一条指令，数据地址告诉某条访存操作去哪里取数据。程序计数位置跟踪前者；栈指针通常指向当前运行栈顶部。返回地址是调用结束后应恢复执行的指令地址，它保存的是控制流位置，不是函数计算出的返回值。

进程通常有自己的地址空间，线程是进程里的一条执行活动。并发允许多个活动交错推进，并行强调实际同时运行。共享对象允许多条执行流访问，但正确性还取决于生命周期与同步。原子操作不可分割地完成指定单次操作，互斥锁用于保护一段满足共同规则的临界区，条件变量用于等某个状态可能改变。

异常是处理器改变常规控制流的一类机制，信号是操作系统向程序报告事件的接口之一。缺页可以是异常处理后重新执行原访存，而不向用户递送故障信号。系统调用则是程序主动请求内核服务的受控途径。它们都可能让当前顺序暂停，但保存与恢复的状态、权限和后续动作不同。

虚拟地址是进程使用的位置编号，物理地址对应硬件内存位置。页表保存映射与权限，TLB缓存翻译结果，数据缓存保留数据块。TLB未命中、数据缓存未命中、缺页是三种不同事件。遇到一句“没命中”，必须问清是哪一层。

文件描述符是进程表中的小编号，打开文件描述是记录偏移等状态的内核对象，FILE流还包含用户态库状态与缓冲。两个描述符可共用一个偏移，也可各有自己的偏移；fork可能复制缓冲却保留共享的内核引用。这些关系会在I/O章逐项算，不要求现在背下全部细节。

有定义行为表示语言规则给出了可依赖的语义；实现定义表示实现必须选择并说明某种行为；未定义行为表示标准不再要求为那次程序执行提供结果保证。未定义不等于“随机挑一个合理值”，也不等于“每次必崩溃”。本书每次用到边界，会交代正在模拟硬件位串还是讨论C源代码。

## 课程范围怎样对应

01至03 章讲数据怎样表示；04至07 章讲 C 怎样落实为指令、调用和内存布局；08 章讲多个源文件怎样成为程序；09至10 章讲进程、异常和信号；11至13 章讲地址翻译、分配和输入输出；14至15 章讲线程和同步；16 章补缓存与性能；17至19 章把前面的知识放进完整问题。

本地已收到的教师详细课件集中在引言、整数、浮点与三讲机器表示。后续系统部分按引言列出的 CS:APP 章节范围讲解，属于帮助预习和复习的配套内容，不能伪称每章已有对应的本学期详细幻灯片。第 95 章把直接来源、补充来源和读图范围列出来，便于你回到原资料核对。

你不需要一次把整本书背下来。看到陌生程序，能先写下“它在什么机器上、数据是什么类型、一步会改哪些状态”，就已经有了开始分析的办法。后面的每个章节都在把这几个问题问得更准确。
