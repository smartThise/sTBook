# 汇编：把一句 C 拆成机器能执行的小步

## 寄存器是 CPU 手边的小格子

`%rax` 是 64 位寄存器名，`%eax` 是它的低 32 位，`%ax` 是低 16 位，`%al` 是低 8 位。在 x86-64 中，写 `%eax` 会把 `%rax` 的高 32 位清零；写 `%ax`、`%al` 不会。这一条很容易在逐指令模拟时漏掉。

本书采用 AT&T 语法：**源在前，目的在后**。`movq %rdi,%rax` 是把 rdi 的值复制给 rax，不是反过来。后缀 `b/w/l/q` 分别对应 1/2/4/8 字节。

## 立即数、寄存器、内存不是一种东西

|写法|读法|
|---|---|
|`$8`|数字 8 本身|
|`%rax`|rax 里存的值|
|`(%rax)`|把 rax 的值当地址，访问那个地址的内存|
|`8(%rdi,%rsi,4)`|地址为 $8+R_{rdi}+4R_{rsi}$ 的内存|

例如 rdi=1000，rsi=3，则 `8(%rdi,%rsi,4)` 的有效地址为 1020。缩放因子只允许硬件支持的 1、2、4、8。有效地址不是读出的数据；内存 1020 里可能存着 99。

## `lea` 为何看起来像读内存，却没有读

`leaq 8(%rdi,%rsi,4),%rax` 只计算地址表达式，把 1020 放进 rax；`movq 8(%rdi,%rsi,4),%rax` 则真的访问内存，把那里的八字节读出来。`lea` 还能实现 $3x$、$5x+7$ 等算术，且不修改条件码。

## 逐步走一段

```asm
# long f(long x, long y) { return x + 4*y + 8; }
leaq 8(%rdi,%rsi,4), %rax
ret
```

按这里的 ABI，x、y 分别从 rdi、rsi 进入，返回值放 rax。x=2、y=3 时，结果 $2+12+8=22$。没有内存访问，也没有真正的乘法指令。不要因为出现括号就判断“这里一定解引用”。

符号扩展与零扩展也不同：把八位 `0x80` 符号扩展会得到 -128 的宽位表示，零扩展则得到 128。读反汇编时不仅看寄存器名字，还要看 `movs*`、`movz*` 等指令的扩展方式。

**自测。** rax=4096，内存地址 4096 中存着 7。`movq %rax,%rbx` 和 `movq (%rax),%rbx` 结果各是什么？答：4096 和 7。用“地址的值”和“地址处的值”这两个完整说法，可以减少混淆。
