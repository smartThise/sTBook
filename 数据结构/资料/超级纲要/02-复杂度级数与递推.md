# 循环究竟跑了几次

一段程序有两层循环，未必就是平方时间；一段只有一层循环，也可能跑上指数次。要算成本，先选一项要计数的基本操作，再把它执行的次数写出来。通常选比较、赋值、访问元素等操作即可，因为在固定字长模型中，一轮里有限个此类操作只差一个常数倍。

## O、Ω、Θ分别说了什么

设T(n)表示规模n时的成本。T(n)=O(g(n))表示：存在正常数c和阈值n₀，所有n≥n₀都有T(n)≤cg(n)。它给上界。Ω给下界。Θ同时给两边的常数倍夹逼，说明增长级别恰好相同。

例如T(n)=3n²+7n+20。n≥1时，3n²≤T(n)≤30n²，所以T(n)=Θ(n²)。它当然也属于O(n³)，只是那个上界较松。写了O(n²)以后，不能自动改口说“恰好平方级”；你还没有写下界。

大O也不自带“最坏情况”含义。可以研究最好成本B(n)、最坏成本W(n)、某个概率模型下的期望成本E[T(n)]，然后分别给它们大O或Θ界。“平均”必须说明对谁取平均；“摊还”则在分析一串操作的总账，不需要随机输入。04和28章会具体算这两种账。

## 例1：三角形循环，真的数出每一行

```text
for i = 0 .. n-1:
    for j = 0 .. i-1:
        do_one_operation()
```

n=5时，i=0执行0次，i=1执行1次，接着2、3、4次，总共10次。一般为

$$0+1+\cdots +(n-1)=\frac{n(n-1)}2.$$

为什么这个和是平方级？上界：每行不超过n，共n行，所以最多n²。下界：后半段约n/2行，每行至少约n/2次，所以至少是某个常数倍的n²。上下界一起给Θ(n²)。把正方形切去一半，只改变常数；若要降到线性，必须把总方格数量降到常数倍n。

循环条件本身也要检查。内层为0次时，仍要进行一次条件判断；所有条件判断额外O(n)，不会改变这里的平方级结论，但在主体很少执行的代码中可能成为主项。

## 例2：变量每次翻倍，数的是指数

```text
i = 1
while i < n:
    i *= 2
```

n=20时，循环开始处i为1、2、4、8、16，5轮以后变成32，结束。第k轮以后i=`2^k`，首次达到n需要k=⌈log₂n⌉。因此n≥2时成本为Θ(log n)。n=1不执行循环，边界值单独处理即可。

如果把上限n改成固定常数1024，循环不超过10轮，关于n的成本就是常数。出现`*=2`不代表必有log n；得看它在多大的范围里增长。

还有一种容易混淆的程序：`i=1; while i<n: do i operations; i*=2`。各轮成本为1、2、4、8……，总和小于2n，因此为Θ(n)。轮数是对数级，总代价却是线性，因为每轮越来越贵。

## 例3：步长是i，步数大约是n/i

```text
for i = 1 .. n:
    for j = 0; j < n; j += i:
        do_one_operation()
```

n=8时，各个i对应的内层次数依次是8、4、3、2、2、2、2、1。别把“j每次增加i”读成“内层执行i次”。i越大，一步跨得越远，循环次数越少。

总次数为`Σ ceil(n/i)`。令调和数Hₙ=1+1/2+…+1/n。每个向上取整最多多1，因此

$$nH_n\le \sum_{i=1}^n\lceil n/i\rceil < nH_n+n.$$

Hₙ为什么是Θ(log n)？把分母按1，2到3，4到7，8到15分组。每组大约有`2^k`项，每项大约是1/`2^k`，该组之和在两个正常数之间。共有约log₂n组，所以总和为对数级。于是整个程序Θ(n log n)。

积分也能给更精细的夹逼：`ln(n+1) <= H_n <= 1+ln n`。用积分前先观察函数1/x递减，才能确定每个矩形在曲线上面还是下面；不需要把积分当成凭空出现的公式。

横轴是输入规模，纵轴采用对数刻度，每个主刻度间隔代表乘上一百，而非增加一百。指数曲线看起来接近直线，是取了对数纵轴后的显示效果；它在规模四十时已约一万亿，平方曲线只有一千六百。画图坐标本身也需要阅读，不能只看线弯不弯判断增长。

## 常见级数，用状态变化来认

等差和`1+2+…+n`对应每轮多做一点，增长为Θ(n²)。几何和`1+2+4+…+2^k`由最后一项的常数倍控制，若最后一项约为n，和就是Θ(n)。平方和`1²+2²+…+n²`为Θ(n³)：上界n×n²，下界后n/2项每项至少(n/2)²。一般固定p≥0时，`Σ i^p=Θ(n^(p+1))`。

倒数平方和`Σ 1/i²`却有常数上界。按2的幂分组，第k组最多`2^k`项，每项至多1/`2^(2k)`，该组不超过1/`2^k`；所有组再相加，是收敛的几何级数。因此看到求和号，不能一律乘一个n。

对数和`Σ log i`等于log(n!)。上界n log n；后半n/2项每项至少log(n/2)，所以为Θ(n log n)。后面比较排序的下界会再次出现这个数量。

## 例4：递归树，每层到底付多少钱

归并排序将长度n的数组分成两半，递归排好，再用线性时间归并。先假设n是2的幂，递推为

$$T(n)=2T(n/2)+\Theta(n),\qquad T(1)=\Theta(1).$$

根这一层合并n项。下一层有2个问题，每个合并n/2项，总共仍n项。再下一层4个问题，各n/4项，总共还是n。直到问题大小为1，共log₂n层非叶合并，每层Θ(n)，所以Θ(n log n)。叶子有n个，共Θ(n)，不改变结果。

如果每个节点只做常数工作，递推改成`T(n)=2T(n/2)+Θ(1)`，每层成本是1、2、4……，最后一层约n，所以总成本Θ(n)。同样两个递归调用，合并成本不同，答案就不同。

如果只有一个子问题：`T(n)=T(n/2)+Θ(n)`，层成本n、n/2、n/4……，总共Θ(n)。而`T(n)=T(n-1)+Θ(n)`的层成本n、n−1……，则为Θ(n²)。先画两三层，再套定理，更不容易把公式放错位置。

## 主定理是一个有条件的工具

对形如`T(n)=aT(n/b)+f(n)`的规则递推，a≥1、b>1为常数。`n^(log_b a)`反映叶子的规模。若f比它多项式地小，叶子主导；若f与它同阶，通常多一个log n；若f比它多项式地大，且满足常用的正则条件，则本层大工作主导。

例如2T(n/2)+n符合相等情形，得n log n；4T(n/2)+n，叶子规模n²大于n，得n²；2T(n/2)+n²，本层为平方级，且2(n/2)²=n²/2满足正则条件，得n²。

`T(n)=T(n/2)+T(n/4)+1`不符合“所有孩子大小都为n/b”的形式，不能把两个孩子硬说成2T(n/2)。32章会把n=`2^k`后转成Fibonacci递推，得Θ(`n^(log₂φ)`)。更一般的Akra–Bazzi方法可处理不同比例，但其应用同样有连续性、增长与扰动范围等条件；不能把“任意递推都可套”当成结论。

## 时间之外，再数同时活着的空间

递归调用树可能总共有n个节点，但不会所有调用同时占着栈。深度优先执行时，一条从根到当前节点的路径上的调用尚未返回。二分递归若每层只存常数局部变量，调用栈是O(log n)。线性递归每次n−1，栈深可达O(n)。

归并排序通常还需要一个长度n的辅助数组，空间为O(n)，这比O(log n)调用栈大。若在每层都复制子数组，某些语言的切片还会带来额外分配和复制；复杂度分析必须对应实际实现。

## 对数变换会保留哪些界

若T(n)≤c f(n)，取对数得到log T≤log c+log f。要把右侧写成O(log f)，还需要log f最终为正且不会趋近0，例如f最终至少为某个大于1的常数。若f恒等于1，log f=0，而T恒等于2仍有T=O(f)，但log T=1不能是O(0)。边界条件不能在取对数时消失。

反方向也不成立：log T=O(log f)只给出T≤`f^c`乘常数，不能推出T=O(f)。例如T=n²、f=n，log T=2log n，确实同阶；T/f=n却无界。指数函数会把对数域里的常数倍放大成幂次，这正是信息损失的位置。看到复杂度函数先取对数再比较，应把常数移回原空间重新检查。

小o记号比大O更强。f=o(g)表示对任意ε>0，充分大时|f|≤ε|g|，常用正函数下相当于比值趋0。n=o(n log n)，因为比值1/log n趋0；n=O(n)成立，却不是n=o(n)。小ω反过来表示比值趋无穷。符号相似，但严格增长与常数倍同阶不能混为一谈。

## 代入法怎样补一个递归树的直觉

递归树给出T(n)=2T(n/2)+n约为n log n以后，可用归纳验证上界。假设较小规模T(m)≤c m log₂m，再代入得T(n)≤2c(n/2)log₂(n/2)+n=c n log₂n−cn+n。取c≥1便不超过c n log₂n，基础小规模再选足够常数覆盖。下界也能按每层至少cn工作与层数给出，不能只凭上界就写Θ。

有时猜T(n)=cn不够。例如T(n)=T(n/2)+n，代入cn得到cn/2+n，要求c≥2，可成立；但T(n)=2T(n/2)+n代入cn会变cn+n，无论c多大都无法压回cn，说明线性猜测不够。代入失败也可能只是猜式缺一个减常数或低阶项，需结合递归树判断。

非二次幂输入可以把数组分成floor(n/2)与ceil(n/2)，最长深度不超过ceil(log₂n)，每层元素总数仍n，所以同阶证明不依赖完美均分。写教材时先用2的幂看结构是简化推理，最后仍应交代一般整数规模。

## 封底估算要用增长比，而非只背秒数

假设每秒能做一亿次某种简单操作，这是估算假设，不是所有机器与所有指令的承诺。n=10⁵时，n²约10¹⁰，单靠常数优化通常救不了平方扫描；n log₂n约1.7×10⁶，则在许多场景里有余地。内存访问、字符串比较与分配比一个整数加法贵，估算应留余量。

指数枚举更要早算：2²⁰约一百万，2³⁰约十亿，2⁴⁰约一万亿。把n=40分两半，各2²⁰项，能从不可行数量降到可处理列表，这是PA Gift的来由。它仍然指数，只是可承受规模区间被改变。

## 分数次成本从哪里来，机器明明只做整数次

调和和式里出现n/i，不表示程序真的执行半次操作，而是用连续量夹住整数计数。若一次循环实际ceil(n/i)次，便有n/i≤次数<n/i+1。每项误差小于1，n项总误差小于n，主项若为n log n，这份误差不会改变阶。把取整界写出来，分数估计就与整数执行建立了联系。

若主项本来只有常数或对数，累计n个取整误差反而可能成为主导，不能在所有求和里都随手丢掉。分析floor(n/i)时，也要保留每项至多1的误差，再看总和量级决定是否可忽略。渐近简化是证明之后的结论，不是先把麻烦符号全部删掉。

对数底数同样只在固定底数之间差常数倍：log_a n=log_b n/log_b a，a、b为固定大于1常数，因而同Θ级。若底数随n变化，例如log_n n=1，就不能再把它与log₂n当同阶。32章迭代对数也必须固定使用的底与停止阈值后才谈精确次数。

## 固定多项式间隔，比任何固定对数幂都强

比较n log n与n的一点零一次方，较小规模可能前者更大，但当n无界增长，log n相对n的零点零一次方最终趋于零。因此前者渐近更小。阈值可能极其巨大，渐近优劣并不保证手边规模上的实际快慢。

将n写成二的k次方后，问题变成比较k与某个固定底数大于一的指数增长；指数最终超过线性或任何固定次多项式。这是主定理里“多项式地小或大”的来由：需要固定正指数间隔，而非只知道某项偶尔小一点。若比较n与n除以log n，两者只差对数因子，不属于固定多项式间隔，不能直接塞进最简单主定理的第一种情况。

最后还要分清算法与问题。一个算法平方时间，并不证明这个问题必须平方时间；最大区间从立方降到线性就是反例。要给问题下界，必须约束所有符合模型的算法，而不是只分析手中这一段代码。

## 练习与完整答案

**练习1。** `i=0,j=1; while i<n: i+=j; j+=1`执行几轮？列出n=10的状态。

解答：每轮结束后i依次1、3、6、10，j依次2、3、4、5，共4轮。k轮后i=k(k+1)/2，所以最小k满足k(k+1)≥2n，k=Θ(√n)。只看到“while i<n”无法决定次数；i每轮的增量由另一个状态j控制。若j从0开始，则第1轮i不动，精确轮数不同，渐近阶仍为平方根。

**练习2。** 比较A：`T(n)=3T(n/3)+n`，B：`T(n)=T(n-1)+1`。哪一个调用树节点更多？哪个时间更长？

解答：A每层总工作n，约log₃n层，时间Θ(n log n)；它的满三叉调用树叶子约n，节点总数Θ(n)。B是一条n层长链，每层常数工作，节点数Θ(n)，时间Θ(n)。两者节点数同阶，节点本身的工作不同，时间可以不同。A的调用栈深Θ(log n)，B的调用栈深Θ(n)，也再次说明总调用数与同时占用的栈深是不同指标。

**练习3。** 有人对`1+2+4+…+n`写出O(n log n)，理由是“约log n项，每项最多n”。这个答案是否错误？

解答：作为上界，它成立；作为紧确增长级别，它太松。设n=`2^k`，总和=`2^(k+1)`−1=2n−1，所以Θ(n)。分析时允许先写一个松上界帮助判断，但最终题目若问渐近复杂度，应继续找匹配下界，或者给精确和式再化简。

单独计算上界以后，再问一个合法输入能否达到同阶成本，能帮助你区分松上界与紧确界。
