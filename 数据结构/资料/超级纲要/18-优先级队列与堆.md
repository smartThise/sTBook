# 优先级队列：每次先取最重要的，不必把全部排好

## 堆不是有序数组

最小二叉堆只保证父节点≤孩子，兄弟之间、两棵子树之间不保证全局有序。完全二叉树可紧凑放进数组：零基下标 i 的孩子是2i+1、2i+2，父是 floor((i-1)/2)。根是最小项，但中序遍历不一定有序。

插入先放末尾，再沿父链上滤；删最小值时拿最后一项补根，再与更小的孩子交换下滤；两者最坏 O(log n)，看最小 O(1)。每次交换应同步更新外部位置索引，否则 decrease-key 等接口可能找错元素。

## 建堆为什么不是 n log n

自底向上，对最后一个内部节点开始依次下滤。高度为 k 的节点约不超过 n/2^{k+1}，每个最多移动 k 层，总成本

$$O\left(n\sum_{k\ge0}\frac{k}{2^k}\right)=O(n).$$

大多数节点靠近叶子，根虽然要下滤很远，却只有一个。把每个节点都按树高 log n 收费，会得到不紧的 O(n log n) 上界。

## 锦标赛树、多叉堆与左式堆

锦标赛树保存两两比较的胜者，最优项在根；更换一个参赛者只更新它到根的路径，适合多路归并。败者树保存失败者信息，是相关但不同的组织方式。

d 叉堆把树高降为 log_d n，但每次下滤要找 d 个孩子中最优者，比较总量约与 d log_d n 有关；不能只因为树更矮就断言越多叉越快。

左式堆着眼于快速合并，维护左孩子的零路径长度不小于右孩子。合并沿右脊递归，再必要时交换孩子，保证右脊短。它不要求整棵树像 AVL 一样左右高度接近；“左式”约束与普通高度平衡不同。

**自测。** 堆排序稳定吗？答：常见原地二叉堆排序不稳定，因为远距离交换可能颠倒相等关键字的原顺序。需要稳定性时必须额外设计，而不是换成 `<=` 就完事。
