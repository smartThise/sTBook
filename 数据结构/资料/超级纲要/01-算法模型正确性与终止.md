# 一段程序凭什么值得相信

给你数组`[6, -2, 5, 1]`，求所有元素的和。你可以在脑中算出10；计算机需要明确到“当前访问哪一项”“下次访问哪里”“什么时候停止”。算法就是这样一套可执行的步骤。数据结构决定数据怎样保存，算法决定怎样访问和修改它们。

课件里曹冲称象的例子有一个有用的细节：先记下大象使船下沉后的水位，再换成石头，直到水位相同。水位把“物体的重量”变成可以复现的状态。换物体时必须保持船和测量条件相同；船若漏水，水位相同就未必对应同样的物体重量。算法也依赖条件，证明要把这些条件写出来。

## 先把题目说完整

求和的输入可以写成：给定长度为n的整数数组a，n是非负整数。输出为所有项的数学和。这里允许空数组，其和定义为0。再加一个工程条件：计算中使用的整数类型能够保存每个中间结果。若题目要求的是对某个模数取余，应明确写在输出定义中，不能把溢出当成取模的替代品。

下面用Python展示步骤；Python的整数会自动增长，因此没有固定64位溢出，但大整数变长后，每次相加的成本也会增长。

```python
def total(a):
    s = 0
    i = 0
    while i < len(a):
        s += a[i]
        i += 1
    return s
```

输入约定叫前置条件，输出应满足的关系叫后置条件。这个说法看起来正式，其实就是“你给我什么”“我承诺还给你什么”。如果函数需要已排序数组，排序就是前置条件；若调用者给乱序数组，不能再使用那份只针对有序输入的证明。

## 例1：每一轮开始，变量到底代表什么

跟踪`[6, -2, 5, 1]`：

|轮次开始的i|轮次开始的s|此时已经处理的元素|本轮动作|
|---:|---:|---|---|
|0|0|没有|加6，然后i变1|
|1|6|6|加−2，然后i变2|
|2|4|6, −2|加5，然后i变3|
|3|9|6, −2, 5|加1，然后i变4|
|4|10|全部四项|条件不成立，结束|

我们要表达的规律是：每轮开始时，`0 <= i <= n`，并且s等于`a[0:i]`中所有元素的和。方括号切片`a[0:i]`表示下标从0到i−1的元素。规律在每轮都保持，所以叫循环不变式。

证明分三步。开始时i=0、s=0，前0项的和确实是0。假设某轮开始时规律成立，本轮将a[i]加进去，再让i增加1，s便等于新的前i项之和，规律继续成立。循环结束时条件`i<n`为假，结合`i<=n`可得i=n，于是s就是全部元素的和。

这个证明覆盖了空数组：初始i=n=0，循环一次也不执行，返回0。它也覆盖负数，因为证明用的是加法关系，没有偷偷假设每一项为正。

## 不变式还没有证明它一定结束

写一个死循环，同样可以保持“s等于前i项之和”：只要循环里什么都不做，s和i便永远符合初始关系。为说明程序会结束，还需要找一个非负整数，证明它每轮严格减小。本例可以用n−i。它从n开始，每轮减1，最多经过n轮就变为0。这样的量常叫下降量。

“非负整数”不能随便改成“非负实数”。实数序列1、1/2、1/4、1/8可以永远减小而不达到0。下降量的取值空间必须不允许无穷严格下降，才足以推出有限终止。

部分正确性是“如果结束，答案正确”；终止性是“它会结束”。两者合起来，才能保证每个合法输入都得到正确答案。这个区别在递归中也一样：递归调用参数变小，必须小到某个明确的基础情况，而且不能越过基础情况。

## 例2：最大值，错一行初始化就换了一道题

试求`[-8, -3, -5]`的最大值。如果令`best=0`，每一项都无法更新best，最后得到0，而输入中根本没有0。正确写法之一是要求n>0，让`best=a[0]`，再扫描剩下的元素。

初始best=−8。读到−3，因为−3>−8，更新best=−3。读到−5，不更新，结果−3。对应不变式是“处理完前i项以后，best等于这i项的最大值”。初始化处理了第1项，所以循环应从i=1开始。若接口必须接收空数组，可以返回一个明确的“无最大值”结果，或者抛出异常；这属于接口设计，不能悄悄捏造0作为答案。

找最大值需要至少检查全部n项。若有一项没看过，把那一项改成比其他所有项都大的数，程序的执行仍一模一样，却必须给出不同答案，矛盾。因此普通未排序输入中，最坏至少需要线性数量的读操作。这里的下界来自“尚未读取的位置可以藏着答案”。

## 例3：辗转相除，下降量能把递归讲明白

求正整数48与18的最大公因数。最大公因数是同时整除两个数的最大正整数。用48除以18，余12，因此`gcd(48,18)=gcd(18,12)`；接着余6，得到`gcd(18,12)=gcd(12,6)`；再余0，得到答案6。

为什么可以丢掉48，只留下18和12？因为48=2×18+12。若d同时整除48和18，就也整除12；反过来，若d同时整除18和12，也整除48。两组数的公因数集合相同，因此最大公因数相同。

```python
def gcd(a, b):
    # a >= 0, b >= 0，且不同时为0
    while b != 0:
        a, b = b, a % b
    return a
```

每轮保存“当前a、b的最大公因数等于原输入的最大公因数”。新的b是旧a除以旧b的余数，满足`0 <= 新b < 旧b`。所以b是非负整数下降量，必然变为0。这一次，等式负责正确性，余数范围负责终止性。它们各干一件具体的事。

最坏轮数是对数级，而不是简单由“b每次变小”直接推出。连续两轮以后较大的参数至少减半，可推出轮数O(log max(a,b))；更精细的最坏输入与相邻Fibonacci数有关。若输入是大整数，整除一次的位运算成本仍应另计。

## 机器模型：什么算“一步”

分析数组扫描时，我们常把读`a[i]`、比较和普通整数加法各算常数次。这对应RAM模型的一个版本：内存单元能按地址直接访问，每个机器字能容纳下标及通常的数据。该模型适合解释数组与链表等结构的操作成本。

若有一个长度为一百万位的整数，把它和另一个同样长的整数相乘，不能继续说“一条乘法指令，所以O(1)”。普通处理器一次只能处理有限位数，大整数库需要许多字操作。某些习题明确假设无限字长、移位为单位成本；可以在该模型下求答案，但不要直接把模型结论当作真实C++的运行时间。

输入大小也要说清。程序枚举1到N用了Θ(N)次；可是把N以二进制写给程序，只需大约log₂N位。令输入位数为b，N可以接近`2^b`，于是这个算法按输入位数可能是指数时间。一层循环照样可能很慢。

## 随机过程与通用停机判定

每轮独立掷公平硬币，正面就停止。恰好第k轮停止的概率是`2^(−k)`，永远不出正面的概率为0，期望轮数为2。但对于任意有限的上限m，连续m轮反面仍有正概率`2^(−m)`。所以“概率1终止”与“有一个统一有限最坏轮数”是不同的承诺。

一般程序的终止性没有万能判定器。假设有程序H能对任何程序P及输入x判断会不会停机。构造D：先问H“D对自身输入会停吗”；H说会停，D就无限循环；H说不会停，D就马上结束。无论H回答什么都会错。这说明不能对所有任意程序实现这样的完美判定器，并不妨碍我们对求和、二分和欧几里得算法分别给出证明。

## 再看一次机器：二进制加一怎样在纸带上执行

图灵机把数据写成带子上的符号，读写头一次观察一个格子，并根据当前状态决定写什么、向哪移动、换什么状态。它不会一次看见整串数字，所以“加一”也必须拆成小动作。假设二进制串最高位在左，头开始在最右位。加一时，遇0就改1并结束进位；遇1就改0，向左继续；若一直越过最高位，则在左侧空格写1。

对1011加一：最右1改0，状态变为仍有进位；再遇1改0；再遇0改1，进位消失，剩下最左1不动，结果1100。对111加一，会把三个1都改0，左侧空格写1，得1000。对1000加一，只需把最后0改1，得1001。如果要求执行结束后读写头回到某个固定起点，还要把移动回去的成本计入。

这个例子说明，数学上一个“+1”与某台机器的一条指令并不总是同一件事。长度b的二进制数最坏有b个连续末尾1，进位会走Θ(b)格；RAM字内加法常被模型视为O(1)，是把有限字长硬件操作作为基本单位。两种分析描述不同模型，不矛盾。

减一也可以自己设计：遇1改0并结束借位，遇0改1并继续向左。1000减一，三个末尾0依次改1，再把最高1改0，得到0111，按表示约定去前导0后为111。输入0若仍要求非负整数，则没有合法结果，应由接口拒绝，不能无限向左借位。

## 当“验证答案”比“找答案”容易

给出整数221，想分解成两个大于1的因子。找到13×17可能要试许多候选，但别人给出13与17后，乘一下就能核对221。验证某一份候选只需检查它满足的关系；验证算法对所有输入正确，还要说明搜索不会漏掉任何可能因子并会终止。

朴素试除只需到平方根：若N=ab且a,b都大于√N，则乘积会大于N，矛盾，所以合数至少有一个因子不超过√N。对221试2、3、5、7、11、13时找到13，再除得17。若只试奇数，仍必须单独检查2。素数输入会一直试到√N附近，成为这种实现的坏情况。

若N以b位二进制给出，√N可接近`2^(b/2)`，所以试除按数值看是平方根级，按输入位数看仍可能指数。这个具体问题把输入编码、基本操作成本与最好最坏情况连在一起：重复除2很快的偶数，不能代表难分解的奇数实例。

测试中找到一份因子可以证伪“它是素数”；测试许多候选都没找到，只在你已经覆盖全部必要候选后才能推出素数。算法证明中的覆盖范围，决定“没找到”能不能变成一个可靠答案。

## 自己做，再核对

**练习1。** 下面的循环想把a原地倒置：`i=0,j=n-1; while i<j: swap(a[i],a[j]); i+=1; j-=1`。给出不变式与下降量，并追踪`[1,2,3,4,5]`。

解答：保存一份只用于证明的原数组b。在每轮开始，i左边的位置都已满足`a[k]=b[n-1-k]`，j右边的位置也满足同样关系，中间`[i,j]`还待处理。第一次交换后数组为`[5,2,3,4,1]`，i=1,j=3；第二次为`[5,4,3,2,1]`，i=j=2。中间只剩一个元素，它本来就在对称中心。下降量可取尚未确定的元素数j−i+1，执行一轮就减少2；只在i<j时执行，因此不存在无限下降。n=0、n=1都不进入循环。

**练习2。** 程序将正整数x反复执行`x=x//2`，直到x=0。有人说“每次至少减1，因此时间Θ(x)”，哪里不够？

解答：至少减1只能给出O(x)上界，不能证明线性下界。取x=20，状态依次20、10、5、2、1、0，共5轮。执行k轮后为⌊x/`2^k`⌋；首次为0发生在k=⌊log₂x⌋+1，因此时间Θ(log x)。终止证明与紧确复杂度证明所需的信息量不同：知道会变小足以证明结束，算多快要知道每次缩小的比例。

继续阅读时可以把本章的证明方法贴在每个算法旁边：输入条件、变量含义、保持关系、下降量、结束后得到的结论。具体内容会变，检查的对象不会消失。
