# 算法的要素、计算模型与正确性

一头大象站上船，船身下沉，吃水线到达某个位置。把象牵下船，往船里装石头，直到船沉到同一条刻痕。这些石头可以一块块搬下来称重，加起来就是大象的重量。曹冲的办法里没有神秘成分：象的重量被转换成水的浮力指示，再转换成石头的重量，而石头可数、可称。整个过程借助明确的工具（船、水、石头），遵循明确的规则（刻痕、装载、逐块称量），每一步都机械可执行。这正是一般意义上的计算：**借助某种工具，遵照一定规则，以明确而机械的形式进行的信息处理**。

上述转换之所以成立，是因为船的吃水深度只取决于总载荷，这个"只取决于"就是工具提供的保证。任何计算模型都要先交代清楚这类保证，否则"一步操作"无从谈起。讨论算法之前，先把工具与规则本身说清楚。

## 计算模型决定什么能算、代价几何

给定平面上一条线段 $AB$，要求把它三等分。带刻度的尺子量出 $|AB|/3$ 就能完成，但尺规作图的两件工具——直尺没有刻度，圆规只能画圆——都不提供"量长度再除以三"的操作。在尺规这套计算模型下，可行的办法是：

1. 从 $A$ 引一条不与 $AB$ 重合的射线；
2. 在射线上用圆规连续截取三段等长，依次得 $C'$、$D'$，即 $|AC'|=|C'D'|=|D'B'|$；
3. 连接 $B'B$；
4. 过 $D'$ 作 $B'B$ 的平行线，交 $AB$ 于 $D$；
5. 过 $C'$ 作 $B'B$ 的平行线，交 $AB$ 于 $C$。

由平行线分线段成比例，$|AC|:|CD|:|DB|=|AC'|:|C'D'|:|D'B'|=1:1:1$，三等分完成。其中"过直线外一点作平行线"本身也是尺规可完成的操作，它在整个作图中被调用了两次，地位相当于程序里的子程序。

这个例子把"计算机"一词的含义摊开了：所谓计算机，就是某个计算模型下的信息处理工具。尺规是一台计算机，曹冲的船也是，下文的图灵机和RAM也是。一台计算机能解决什么问题、每步操作代价几何，都由模型规定；同一个问题换一个模型，可行性与成本都可能改变。

**算法定义**：在特定计算模型下，旨在解决特定问题的指令序列。

定义里的每件东西都要落实。指令序列由基本操作组成，那么基本操作必须真的基本；解决特定问题，那么输入输出必须有定义；"旨在解决"，就要求它确实解决。下面逐项展开。

## 算法的要素

**输入与输出**。输入是待处理的信息，即问题的实例；输出是经处理的信息，即问题的答案。零个输入的算法允许存在（比如打印一张固定表格），输出不能缺席，没有输出就没有"答案"可言。

**正确性**。算法的确可以解决指定的问题。这句话比听上去强：不是"对某些输入给出像样的结果"，而是对每一个合法实例都给出符合要求的输出。怎样把"正确"变成可以论证的命题，本章稍后用排序算法完整演示一次。

**确定性**。算法可描述为由基本操作组成的序列，任何时刻下一步做什么没有歧义。菜谱里的"加盐少许""煮至半熟"违反这一条：多少是少许，多熟算半熟，两个人执行会得到不同结果。算法的每一步无歧义，同一输入重复执行，中间过程与输出都应一致。

**可行性**。每个基本操作都可实际实现，且在常数时间内完成。"把大象放进冰箱"分三步写的笑话之所以可笑，是因为第二项操作不可行。同样，"将这 $n$ 个数排序"不能作为一个基本操作写进算法，它本身就是待解决的问题。基本操作必须小到模型可以直接完成：一次加法、一次比较、一次读写头移动、一次寄存器访问。

**有穷性**。对任何输入，算法经有穷次基本操作后停止并给出输出。这一条最容易出事，下一节专门讨论。

## 有穷性：看起来正常的循环可能停不下来

考察著名的Hailstone序列（冰雹序列）：从任意正整数 $n$ 出发，若 $n$ 为奇数则变为 $3n+1$，若为偶数则变为 $n/2$，反复进行。写成程序：

```c
int hailstone( int n ) {
   int length = 1;                 //从n出发，序列长度至少为1
   for ( ; 1 < n; length++ )       //n尚未降到1，就继续
      n = ( n % 2 ) ? 3 * n + 1 : n / 2;
   return length;                  //返回序列总长度
}
```

这个函数对很多输入运行良好。取 $n=27$ 逐步执行：$27\to82\to41\to124\to62\to31\to94\to47\to142\to71\to214\to107\to\cdots$。这条序列并不温和：中途冲到过峰值 $9232$，绕了远路才一路折回，总共经过112个数到达1。$n=7$ 时长度为17，$n=100$ 时长度为26，都可以逐项验证。

问题在于：**所有**正整数最终都会降到1吗？对这一个具体函数，迄今没有人能证明，也没人找到反例。Erdős对此的评价是：数学还没有准备好对付这类问题。于是在定义层面出现了一件事：`hailstone()`是一段语法正确、对已测输入都能停止的**程序**，但在有穷性被证明之前，它还不配称为**算法**。正确性与可行性它都满足，唯独有穷性悬而未决。有穷性被单列为算法要素，原因就在这里：它不是形式条款，而是实实在在可能缺失的性质。

随机性带来另一种微妙情况。假设`rand()`是理想的随机整数发生器，产生奇数与偶数的概率各为 $1/2$，考察

```c
void toss() { while ( rand() & 1 ); }   //rand()为奇数就继续循环
```

循环体为空，作用是反复掷硬币，直到掷出偶数。理论上它可能永远不停：第 $k$ 次判定才首次遇到偶数的概率是 $\left(\tfrac12\right)^k$，对每个有限的 $k$ 都大于零，"任意多步之后仍在循环"始终可能。但期望有限：首次遇到偶数所需的判定次数服从几何分布，期望为

$$\sum_{k \ge 1} k \cdot \Big(\tfrac12\Big)^k = 2,$$

平均两次判定就停下来，迭代次数期望为1，是常数。`toss()`以概率1在有穷步内停止，期望耗时还是常数，可它并不**必然**停止。按算法定义的严格字面，它同样只是程序：有穷性要求对一切输入必然停止，"几乎必然"和"期望常数"都不够。

两个例子说明同一件事：判断一段代码是不是算法，不看它写得像不像，只看它的有穷性能否成立。已证明的成立，未证明的存疑。

## 正确性：把"排好序"变成可以论证的命题

下面完整分析一个排序算法。任务：把 $n$ 个整数的数组调整为非降序。算法是起泡排序的基础版本：

```c
void bubbleSort( int A[], int n ) {
   while ( 1 < n-- )                  //做n-1趟起泡扫描
      for ( int i = 0; i < n; i++ )   //自前向后，逐对检视相邻元素
         if ( A[i] > A[i+1] )         //一旦逆序
            swap( A[i], A[i+1] );     //则交换
}
```

`while ( 1 < n-- )`先判断`1 < n`是否成立，再将`n`减1。初始 $n=7$ 时，判断用的是7，判断后`n`变为6，本趟扫描检视下标0至5的六对相邻元素。循环反复进行，直到某次判断时`n`已不大于1。用具体数组执行一遍，取

$$A = \{\,5,\ 2,\ 7,\ 4,\ 6,\ 3,\ 1\,\}$$

**第1趟**（扫描范围为下标0至5）。逐对比较，逆序即交换：

|比较对|结果|动作|交换后的数组|
|---|---|---|---|
|(0,1)|5 > 2|交换|[ 2, 5, 7, 4, 6, 3, 1 ]|
|(1,2)|5 < 7|不动|[ 2, 5, 7, 4, 6, 3, 1 ]|
|(2,3)|7 > 4|交换|[ 2, 5, 4, 7, 6, 3, 1 ]|
|(3,4)|7 > 6|交换|[ 2, 5, 4, 6, 7, 3, 1 ]|
|(4,5)|7 > 3|交换|[ 2, 5, 4, 6, 3, 7, 1 ]|
|(5,6)|7 > 1|交换|[ 2, 5, 4, 6, 3, 1, 7 ]|

7一路向右换位，每换一次前进一格，最后停在末尾。这不是巧合：扫描中每处理完一对 $(i, i+1)$，二者中较大者总位于 $i+1$ 处；下一对又以这个较大者为左项继续比较。于是"当前见过的最大者"始终待在扫描前线上，扫完全部相邻对后它必然落在最后一个位置。第1趟结束时数组为

```text
下标    0   1   2   3   4   5   6
       [2] [5] [4] [6] [3] [1] [7]
        └─────── 无序前缀 ───────┘ └ 已就位 ┘
```

**第2趟至第6趟**做同样的扫描，只是每趟的扫描右端缩短一格：末尾已就位的元素不再参与比较。各趟结束后的完整状态：

|趟|扫描范围|趟结束时的数组|新就位的元素|
|---|---|---|---|
|1|0–5|[ 2, 5, 4, 6, 3, 1, **7** ]|7|
|2|0–4|[ 2, 4, 5, 3, 1, **6**, 7 ]|6|
|3|0–3|[ 2, 4, 3, 1, **5**, 6, 7 ]|5|
|4|0–2|[ 2, 3, 1, **4**, 5, 6, 7 ]|4|
|5|0–1|[ 2, 1, **3**, 4, 5, 6, 7 ]|3|
|6|0|[ 1, **2**, 3, 4, 5, 6, 7 ]|2|

第6趟之后判断`1 < 1`不再成立，算法停止。逐格核对可知任何相邻两项都满足左项不大于右项，排序完成。以上是"这一次运行结果正确"，接下来论证"任何输入都正确"。

将数组在任何时刻分成两段：前缀 $[0, s)$ 与后缀 $[s, n)$。称一个状态满足**序列模式**，若后缀已经非降序，且后缀中的每个元素都不小于前缀中的任何元素。初始取 $s=n$，后缀为空，模式平凡成立。此后每做一趟扫描：

**实质**：前缀中的最大元素必然被推到前缀末尾，即 $s-1$ 处。第1趟的逐步表演示了这个推进机制，对任意前缀同理。

**不变性**：一趟扫描后序列模式依然保持。新进入后缀的元素是原前缀的最大者，它不小于新前缀中的任何元素；后缀其余部分未动，仍非降序。

**单调性**：每趟扫描使 $s$ 减1，后缀长度加1。

单调性保证至多 $n-1$ 趟后 $s$ 减到1；此时后缀 $[1,n)$ 非降序且每个元素都不小于 $A[0]$，整个数组非降序。三点合起来，对任意输入证明了正确性。这个论证的结构值得记住：一个描述中途状态的关系式（序列模式），加上"每次迭代保持它"（不变性），加上"迭代次数有穷"（单调性），缺一不可。之后各章凡是说明"这样做是对的"，用的都是同一套推理骨架。

`bubbleSort()`只用了常数个辅助变量，除输入数组外不占额外空间，这类算法称为**就地算法**（in-place algorithm）。它的比较与交换次数在最坏情况下约为 $n(n-1)/2$ 对，属于 $O(n^2)$ 量级；量级的记号与含义是下一章的主题。

## 从正确的算法到好的算法

正确只是底线。同样排序 $n$ 个数，不同算法的运行时间可以相差十几个数量级，写出正确但低效的算法，实践中接近于没有写出。评价算法还要看：

**健壮性**：能辨别不合法的输入并适当处理，而不是异常退出。声明长度为 $n$ 却传入负数时，可靠的代码应当报告错误，而非越界读写。

**可读性与可维护性**：结构清晰、命名妥当、注释必要，他人半年后仍能读懂并修改。

**效率**：速度尽可能快，占用存储尽可能少。这是本课程的主要研究对象。

Wirth把程序概括为"算法 + 数据结构"，本课程在此之上还乘了一个效率因子：

$$(\text{Algorithms} + \text{Data Structures}) \times \text{Efficiency} = \text{Computation}$$

效率怎么度量、怎样在不同算法之间公平比较，必须先约定统一的账本。计算模型为此再次出场。

## 图灵机：把"一步"拆到不能再拆

要统计算法执行了多少次基本操作，前提是"基本操作"本身有明确定义。图灵机（Turing Machine, TM）把这一点拆到极致。

**构成**。一条纸带（tape），均匀划分为一个个单元格（cell），每格存放一个符号；符号取自某个有限字母表，未写过的格子统一记作`#`。一个读写头（head），任何时刻对准某一格，可读取或改写其中的字符，每拍只能左移或右移一格。读写头总处于某个**状态**（state），每拍按规则转向新状态。所有行为由**转换函数**统一规定：

$$(q,\ c;\ d,\ L/R,\ p)$$

含义：当前状态为 $q$ 且当前格字符为 $c$ 时，把该字符改写为 $d$，向左（L）或向右（R）移动一格，转入状态 $p$。一旦转入状态 $h$ 便停机。从启动到停机经历的拍数即计算时间 $T(n)$，它同时等于读写头累计移动的格数。图灵机的访问是**顺序访问**：想到达第1000格，必须一步步挪过去。

**实例：二进制加一**。纸带上存有一个二进制非负整数，将其加一。加一的实际过程：末尾连续的'1'（可能没有）全部翻成'0'，原先的最低位'0'（或一路翻到头的'#'）翻成'1'，比如 $10101111+1=10110000$。用两个工作状态完成，`<`表示左行、`>`表示右行：

```text
(<, 1; 0, L, <)   //左行途中遇1，翻0继续向左
(<, 0; 1, R, >)   //遇到原有的0，翻1后掉头右行
(<, #; 1, R, >)   //一路翻到头（原数全为1），此处补最高位
(>, 0; 0, R, >)   //右行越过刚翻出的0
(>, #; #, L, h)   //碰到右边界，停机
```

$(<,\ \#;\ 1,\ R,\ >)$不可省略：输入形如 $111$（全'1'）时，左行扫描越过所有'1'直达'#'，必须由这条规则写入新的'1'，否则进位丢失，而且机器在状态`<`读到'#'时将无规则可用。

取纸带内容`##10101111##`（八位二进制数10101111，十进制175），读写头对准最右一位（下标7），初始状态`<`。逐拍执行，`^`标记读写头位置：

|拍|状态|读到|动作|此后纸带|头位置|
|---|---|---|---|---|---|
|1|`<`|1|改0，左移|`##10101110##`|6|
|2|`<`|1|改0，左移|`##10101100##`|5|
|3|`<`|1|改0，左移|`##10101000##`|4|
|4|`<`|1|改0，左移|`##10100000##`|3|
|5|`<`|0|改1，右移，转`>`|`##10110000##`|4|
|6|`>`|0|不动，右移|`##10110000##`|5|
|7|`>`|0|不动，右移|`##10110000##`|6|
|8|`>`|0|不动，右移|`##10110000##`|7|
|9|`>`|0|不动，右移|`##10110000##`|8|
|10|`>`|`#`|不动，左移，停机|`##10110000##`|7|

10拍之后纸带上是`10110000`，即十进制176，恰为175加一。这里 $n=8$ 是输入位数，$T(8)=4+1+4+1=10$：左行翻转四个'1'用4拍，翻转'0'并掉头1拍，右行越过四个'0'用4拍，停机1拍。一般地，若数长为 $n$、末尾连续 $r$ 个'1'，左行耗 $r+1$ 拍、右行耗 $r+1$ 拍，$T(n)=2r+2\le 2n+2$，仍是输入规模的线性函数。

## RAM：把"按编号访问一次"当成一步

图灵机忠于物理直觉，但顺序访问使它连取一个数组元素都要走很多格。随机存取机（Random Access Machine, RAM）对现实计算机做了另一种抽象：

- 寄存器 $R[0],R[1],R[2],\ldots$ 顺序编号，总数没有限制；
- 可通过编号直接访问任意寄存器，即按秩调用（call-by-rank），这正是日后数组与向量访问的原型；
- 设有指令寄存器IR（Instruction Register），指示当前执行的指令；
- 每条基本指令（读取、写入、加减、条件跳转等）只需常数时间。

在这类模型中，算法的运行时间就是它执行的基本操作次数：$T(n)$ 为算法求解规模为 $n$ 的实例所需执行的基本操作次数。模型一旦固定，"数步数"就有了统一而客观的账本，不再依赖具体机器、语言或编译器。

**实例：上整除法**。非负整数 $c$ 存于 $R[0]$、正整数 $d$ 存于 $R[1]$，求 $\lceil c/d \rceil$。思路：反复从 $R[0]$ 中减去 $R[1]$，统计在下溢（减成负数）之前减了多少次。程序共七条指令：

```text
[0] R[3] <- 1             //常数增量
[1] GOTO 4                //若R[0]为0，跳过循环
[2] R[2] <- R[2] + R[3]   //x++
[3] R[0] <- R[0] - R[1]   //c -= d
[4] IF R[0] > 0 GOTO 2    //c仍为正则继续减
[5] R[0] <- R[2]          //否则将计数复制到R[0]
[6] STOP                  //返回R[0]
```

取 $c=25$，$d=12$。每执行一条指令记为一行快照，"^"标记本步被写入的寄存器：

|步|IR|$R[0]$|$R[1]$|$R[2]$|$R[3]$|本步动作|
|---|---|---|---|---|---|---|
|0|[0]|25|12|0|1^|置增量为1|
|1|[1]|^|^|^|1|跳至[4]|
|2|[4]|^|^|^|^|25>0，转[2]|
|3|[2]|^|^|^1|^|$x=1$|
|4|[3]|13^|^|^|^|$c=25-12$|
|5|[4]|13|^|^|^|13>0，转[2]|
|6|[2]|^|^|^2|^|$x=2$|
|7|[3]|1^|^|^|^|$c=13-12$|
|8|[4]|1|^|^|^|1>0，转[2]|
|9|[2]|^|^|^3|^|$x=3$|
|10|[3]|-11^|^|^|^|$c=1-12$|
|11|[4]|-11|^|^|^|非正，顺序执行|
|12|[5]|3^|^|^|^|$R[0]\leftarrow x$|
|13|[6]|3|^|^|^|停机|

输出3，而 $\lceil 25/12\rceil=3$，正确。循环恰好数出上整除的原因：$k$ 次减法后 $R[0]=c-kd$，循环在第 $k$ 次减法后停止，当且仅当 $c-kd\le 0$ 且 $c-(k-1)d>0$，即 $k$ 是满足 $k\ge c/d$ 的最小整数，这正是上整除的定义。$c=0$ 时指令[1]直接跳过循环返回0，与 $\lceil 0/d\rceil=0$ 一致。时间成本等于快照表的高度，即各条指令累计执行次数之和：

$$T(25,12) = 1 + 1 + 4 + 3 + 3 + 1 + 1 = 14$$

依次是[0]、[1]、[4]、[2]、[3]、[5]、[6]的执行次数。

## 两种模型说明了什么

同一个加一问题，图灵机需要来回走带，RAM用一条加法指令完成；上整除在RAM上是十几条指令，在图灵机上则要更长的走带。模型的选取改变"一步"的价格，不改变"算法是基本操作的指令序列"这一本质。两者共同的要点有三条。

其一，模型把平台差异关在门外。同一算法无论用什么语言书写、在什么机器上编译运行，固定模型下的基本操作次数是同一个数，效率评价因此可以客观进行。

其二，时间与空间可以用同一把尺子度量。空间复杂度 $S(n)$ 计输入之外消耗的存储单元数；每次基本操作至多触及常数个单元，$T(n)$ 天然是 $S(n)$ 的上界，所以本课程通常以时间为主要账目，空间在关键处单独核算。

其三，模型中的基本操作对应真实机器的真实动作。RAM的call-by-rank就是数组访问，图灵机的纸带是顺序介质的极限情形。后文设计数据结构时，"这项操作要花多少次基本运算"在每个模型下都有确定含义，正是这些模型在背书。

下一章在这个账本上引入大 $O$ 记号，讨论成本随问题规模增长的趋势。

## 本章要点

- 计算＝借助工具、遵照规则、以明确而机械的形式进行的信息处理；算法定义在特定的计算模型之上，是解决特定问题的指令序列。
- 算法要素：输入、输出、正确性、确定性、可行性、有穷性。Hailstone序列与随机掷币程序说明：有穷性未证明的、只以概率保证终止的，都只能算程序。
- 正确性的论证骨架：状态关系式（如序列模式）＋每步保持（不变性）＋步数有穷（单调性）。
- 图灵机以顺序访问定义"一步"；RAM以按秩访问定义"一步"；固定模型之后，运行时间才可以客观地数。
