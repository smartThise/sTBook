# 字符串匹配：KMP与next表

串匹配（string matching）：在文本$T[0,n)$中定位模式$P[0,m)$。蛮力算法`match`逐对齐位置从头比对，最坏$O(n \cdot m)$——比如$T = 0^{n-1}1$、$P = 0^{m-1}1$，每个对齐都几乎比对到末尾才失败。KMP算法（Knuth-Morris-Pratt, 1977）做到$O(n+m)$，它的洞察只有一句话：**失配之前的每一次成功比对都是信息，失配后正文指针绝不回退**。

## 失配后知道什么：最长自匹配

设失配发生在正文$i$与模式$j$处——即前缀$P[0,j) = T[i-j, i)$已经匹配成功。朴素法把$i$回退到$i-j+1$、$j$清零重比；KMP问：利用已知的$P[0,j)$，能把模式**右移多少而不漏解**？答案是"$P[0,j)$的最长**真自匹配**前缀"：找到最长的$t < j$使

$$P[0,t) = P[j-t, j)$$

模式右移$j - t$位后，这$t$个字符自动匹配（它们在模式内已经互相对齐验证过），比较直接从$i$、$t$继续——**正文指针$i$永不回退**。这份预案完全由模式自身决定，可以**事先构造**：记作next表，$next[j] = t$；约定$next[0] = -1$（失配于j=0时模式整体右移一位、j归零）。

## 查询：化腐朽为神奇

```cpp
int match( char* T, int n, char* P, int m ) {        //KMP主算法
   int* next = buildNext( P );                        //构造next表：O(m)
   int i = 0, j = 0;                                  //正文指针、模式指针
   while ( j < m && i < n )
      if ( 0 > j || T[i] == P[j] ) { i++;  j++; }     //若匹配（或j已到最左），携手前进
      else j = next[j];                               //失配：模式右移，i不动
   delete [] next;
   return i - j;                                      //j==m则命中于i-j；否则n-m+1示意失败
}  //O(n + m)
```

每一轮要么$i$前进（匹配），要么$j$下跳——$j$的下跳累计不超过$i$的前进累计（每次下跳后必有一次匹配使$i$前移），故总比对次数$O(n)$，加上构造$O(m)$，总体$O(n+m)$。

## 构造next表：减而治之

next表自身用KMP的思想构造——模式**与自己**做匹配。已知$next[0..j]$，如何得$next[j+1]$？设$t = next[j]$：若$P[j] = P[t]$，则自匹配延长一格，$next[j+1] = t + 1$；若不等，则按"自匹配的传递链"回退$t = next[t]$再比——下一候选恰是当前的next值，直至命中或$-1$终止：

```cpp
int* buildNext( char* P ) {                    //构造模式P的next表
   size_t m = strlen( P ), j = 0;              //"制表"指针
   int* N = new int[m];                        //next表
   int t = N[0] = -1;                          //模式串最左对齐重启
   while ( j < m - 1 )
      if ( 0 > t || P[j] == P[t] ) {           //匹配
         j++;  t++;
         N[j] = t;                             //改进版此处另作处理（见下）
      } else                                   //失配
         t = N[t];                             //传递链回退
   return N;
}  //O(m)：j至多前进m步，t的回退总量不超过前进总量
```

三处关键回退都能看清"传递链"：j=4时$P[1]=A$与$P[3]=M$失配，回退$t = next[1] = 0$，$P[0]=M$与$P[3]=M$命中，$next[4]=1$；j=5时$A$对$I$失配回退到0，$M$对$I$仍失配退至$-1$，$next[5]=0$；j=6同理得0。

## next的改进：一石二鸟

next表还有一处可打磨：失配于$j$跳到$t$后，若$P[t] = P[j]$，则同一正文字符会再次失配——这次跳转白做。改进版在构造时顺手补刀：命中（$P[j] = P[t]$）时令

$$N[j] = N[t] \quad \text{（而非 } t \text{）}$$

把"必然再次失配"的跳转链一次折叠到位。改进只增加一行，查询效率进一步提升；这正是KMP作为"化腐朽为神奇"的范本被反复称道之处——**预处理换查询**，空间$O(m)$换时间$O(n)$。

## 后继者一瞥：BM与Karp-Rabin

讲义还铺开了两条进阶路线。**BM算法**（Boyer-Moore）：模式**自右向左**比对，坏字符（bad character）与好后缀（good suffix）两张启发式表允许大步跳跃，实际运行常常亚线性。**Karp-Rabin**：为模式与各正文窗口计算滚动指纹（散列，第15章的哈希思想），指纹不等直接跳过、相等再精确验证——把匹配问题转成算术。三者的共同哲学与KMP一致：**预先计算，运行时不再回头**。

## 本章要点

- 蛮力匹配最坏$O(n \cdot m)$；KMP靠"失配信息"$O(n+m)$。
- next[j]＝$P[0,j)$最长真自匹配前缀长度；失配跳转$j = next[j]$，正文指针永不回退。
- next表以模式自匹配构造，减而治之：命中则$+1$，失配沿传递链$next[t]$回退；总体$O(m)$。
- 改进next：$P[t]=P[j]$时取$N[j]=N[t]$，折叠必然失效的跳转。
- BM自右向左+坏字符/好后缀跳跃；Karp-Rabin滚动指纹+验证——共同哲学：预处理换运行时。
