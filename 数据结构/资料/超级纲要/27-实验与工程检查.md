# 一次完整的调试：从错误输出，找到第一步走歪的位置

算法在纸上正确，不表示你写的程序还在执行同一个算法。这里做三次小实验：抓住二分不前进、矩形宽度多1、Gift重复方案被删的问题。输入都很小，错误发生在哪一行可以当场看见。之后再把同一套办法用于链表、树和图。

## 先给程序一个可以被反驳的承诺

以`lower_bound`为例：输入数组`a`已经非降排列，返回下标p，满足

$$0\le p\le n;\quad 0\le i<p\Rightarrow a_i<x;\quad p\le i<n\Rightarrow a_i\ge x.$$

$n$是数组长度，$x$是查询值。p可以等于n，表示整个数组都小于x；这时p是合法的边界，却不是可以读取的元素位置。空数组返回0。存在重复时，返回的是第一项不小于x的位置。

这个承诺描述答案应该具有什么性质，没有规定必须用二分。因此另一个从左到右扫描的程序就能独立提供答案：看见第一项不小于x便返回，否则返回n。它在大输入上慢，但对长度6的测试完全够用，而且不容易和二分共享同一个更新错误。

先把两个常被混淆的接口放在纸上：数组`[2,2,5]`查2，`lower_bound`返回0；课程C版查找返回“最后一个不大于2”的位置1。两份程序若各自实现这两个不同承诺，输出不同并不说明其中一个算错。测试前必须先固定规格。

## 实验一：让错误二分停下来，交出重复的状态

错误更新是`lo=mid`，持续条件却写`lo<hi`。用数组`[1,2]`查3，半开区间初始`[0,2)`：

| 轮 | lo | hi | mid | 判定 | 更新后未知区间 |
|---:|---:|---:|---:|---|---|
| 1 | 0 | 2 | 1 | 2<3，向右 | `[1,2)` |
| 2 | 1 | 2 | 1 | 2<3，向右 | `[1,2)` |
| 3 | 1 | 2 | 1 | 完全重复 | `[1,2)` |

一个输入就说明“每轮一定缩短”是假的。若测试器只等待返回，它自己也会卡住。调试版可设置步数上限，或者每轮断言新长度严格小于旧长度。这里改为`lo=mid+1`，第1轮后未知区间立即变空`[2,2)`，返回2，表示没有满足条件的项。

下面是一个完整小程序。`bad`参数只用来有意注入这一处已知错误；正常版始终用`mid+1`。`trace`保存每轮的输入状态，报错时不需要再凭记忆复现。

```python
def linear_bound(a, x):
    for i, value in enumerate(a):
        if value >= x:
            return i
    return len(a)


def binary_bound(a, x, bad=False):
    lo, hi = 0, len(a)
    trace = []
    while lo < hi:
        if len(trace) > len(a) + 2:
            raise RuntimeError(trace)
        mid = lo + (hi - lo) // 2
        trace.append((lo, hi, mid))
        if a[mid] < x:
            lo = mid if bad else mid + 1
        else:
            hi = mid
    return lo


a, x = [1, 2], 3
print("slow:", linear_bound(a, x))
print("good:", binary_bound(a, x))
try:
    binary_bound(a, x, bad=True)
except RuntimeError as error:
    print("bad repeats:", error.args[0])
```

输出的慢答案和正确二分都是2；错误版会交出`(0,2,1)`后连续重复`(1,2,1)`的轨迹。步数限制只是让一次坏测试有限结束，不能作为二分正确性的数学证明。真正的终止依据仍是：当lo<hi时，`lo≤mid<hi`，两条正确分支都使非负整数`hi-lo`严格下降。

### 把一个反例扩成有限域穷举

从值域`{-1,0,1}`生成长度0到6的所有非降数组，对每个查询`{-2,-1,0,1,2}`比较两版答案。先只看长度2，全部输入恰是`[-1,-1]`、`[-1,0]`、`[-1,1]`、`[0,0]`、`[0,1]`、`[1,1]`，没有`[1,-1]`，因为它违反非降前提。用`[-1,0]`查0，扫描读−1后在下标1返回；二分先比较下标1的0，保留`[0,1)`，再比较−1，返回1。两条程序经过不同路径，却兑现同一个承诺。

非降数组由三种值各出现几次唯一决定。设次数为u、v、w，长度为r，则`u+v+w=r`。把r个标记排成一行，用两条分隔线切成三段，段长就是三个次数；在r+2个位置中选两处放分隔线，共$\binom{r+2}{2}$种。这也解释了为什么允许某段为空，恰好对应某个值一次都没出现。生成器`combinations_with_replacement`直接列出这些非降序列，不必生成所有乱序排列再去重。

长度0到6合计多少，可以增加第四个次数`s=6-r`，表示还没用的长度；四个非负数相加为6。因此用6个标记和3条分隔线，方案数为$\binom93=84$。每个数组查5个目标，共420次。这个数字只标明测试范围；正确性仍须另外证明。

```python
from itertools import combinations_with_replacement

checks = 0
for length in range(7):
    for values in combinations_with_replacement([-1, 0, 1], length):
        a = list(values)
        for x in [-2, -1, 0, 1, 2]:
            actual = binary_bound(a, x)
            expected = linear_bound(a, x)
            assert actual == expected, (a, x, expected, actual)
            checks += 1
print("bound checks:", checks)
```

420次全过，准确结论是“在这个有限域里与独立扫描全部一致”。它能抓住很多空区间、重复值、末端返回的错误，但没有穷尽任意长度、任意类型，也没有验证C++的整数溢出和对象生命期。测试覆盖范围与算法证明各自写清。

## 实验二：一根柱就能抓到矩形宽度多1

直方图每柱宽1。慢答案枚举每个连续区间`[l,r]`，从左向右延长时维护最小高度，面积是最小高度乘`r-l+1`。快版弹出一根柱时，当前下标i是右侧不可用位置，弹后栈顶left是左侧暂时不能跨过的位置，因此可用格为`left+1`到`i-1`，宽应为

$$i-left-1.$$

用只有一根高度2的柱，末尾补0。原柱下标0被弹出，i=1，left=−1，可用位置只有0，宽$1-(-1)-1=1$，面积2。若漏减1，会算出宽2、面积4。这个反例比一屏随机柱子更能让人看到“多出来的是哪一格”：右边下标1的零柱不该包括，左边−1也不是真柱。

慢程序可以直接写成：

```python
def rectangle_slow(heights):
    best = 0
    for left in range(len(heights)):
        minimum = heights[left]
        for right in range(left, len(heights)):
            minimum = min(minimum, heights[right])
            best = max(best, minimum * (right - left + 1))
    return best
```

先手验几组有不同目的的数据：

| 输入 | 答案 | 专门检查什么 |
|---|---:|---|
| `[]` | 0（若接口允许空） | 不读首元素 |
| `[2]` | 2 | 左右边界不多1 |
| `[2,2]` | 4 | 等高柱如何处理 |
| `[2,1,2]` | 3 | 最矮柱覆盖整段 |
| `[1,2,3]` | 4 | 输入结束要结算未弹柱 |
| `[3,2,1]` | 4 | 一轮连续弹多根 |
| `[0,0]` | 0 | 面积0与并列边界 |

若快程序还要返回“面积相同取最靠左，仍相同取最短”的区间，慢程序也应枚举并比较`(-area,left,right)`。只比较面积会漏掉位置错误；只比较位置也可能漏掉面积错误。测试对象的承诺有几部分，验证器就查几部分。

可以再枚举长度至多6、高度0到3的全部数组，与慢答案比较。枚举范围增大前，先故意把快版宽度改错，确认测试立即拒绝`[2]`。若错误版仍全绿，应该先检查测试是否真的调用了快版、失败是否被吞掉、预期答案是否误用同一个函数算出。

## 实验三：重复的和，为什么不是重复的方案

Gift有两组`(1,1)`、`(2,2)`。每组仍有“选左”“选右”两个动作，四个方案为：

| 选择身份 | 总和 |
|---|---:|
| 左、左 | 3 |
| 左、右 | 3 |
| 右、左 | 3 |
| 右、右 | 3 |

预算3时答案4，预算2时答案0。若优化版把左右半和都放进集合去重，会把`[1,1]`变成`[1]`、`[2,2]`变成`[2]`，只数到1。这次错误不是二分边界，也不是整数算错；它发生在表示法丢掉了选择身份。

独立慢答案枚举每个二进制选择串，对每组按相应位取值，再求和。对小组数，可以把全部预算从“最小总和减1”测到“最大总和加1”。优化版的输出不仅要等于慢答案，还应满足以下可单独核验的关系：交换某组的左右两个选项，方案总数不变；增大预算，答案不减；把每个选项都加c，并把预算加$nc$，答案不变。

负数还可以专测错误剪枝。两组`(5,6)`、`(-10,0)`，预算0，合法总和−5、−4，共2种。如果第一组刚取5或6就因“部分和超预算”剪枝，会把两个合法方案都删掉。只有能证明后面不可能降低总和时，这种剪枝才安全。

## 链表错误要保存操作历史，不能只保存最后一组值

从`H↔A↔B↔T`把B移到A前，预期`H↔B↔A↔T`。验证不能只正向读出B、A，还应从T逆向读出A、B，并检查每对相邻节点互相承认对方：`p.succ.pred==p`、`p.pred.succ==p`。若忘了改A.pred，正向内容可能正确，逆向或后续删除才出错。

保存外部句柄p指向A，再做节点移动、值交换、删除重建，这三个操作的句柄承诺不同。调试日志应记下节点ID、链接ID、size以及操作序列。只保存最终集合`{A,B}`无法复现“先移动再删除”才触发的错误。

发现100步操作后失败，可以试删去前半操作；若仍失败，保留删减，继续缩小。每次删减都要确认前置条件仍合法，且独立验证器仍报告同一种规格失败。逐步缩成3步的反例，比猜100行日志容易得多。随机种子有助复现，但最终还应保存完整失败输入；生成器版本和调用次序变了，种子相同也可能得到不同序列。

## 整数范围先算中间式，再决定类型

逆序数最多$n(n-1)/2$。n=100000时最大为4999950000，超出32位有符号整数。下面两句不是等价的：

```cpp
long long wrong = n * (n - 1) / 2;  // n若为int，乘法可能先溢出
long long right = 1LL * n * (n - 1) / 2;
```

宽变量只能保存右侧计算完成后的值，不能追溯修复窄乘法。叉积的两个大乘积最终相减成小数，乘积仍可能先溢出；带状DP的`inf`若取最大整数，再无条件加1，也可能回绕成负数，伪装成更优解。

内存也按具体对象计算。一个10000×10000的32位表是4亿字节，约381MiB，还没计行对象、指针、输入和递归栈。滚动两行能省表，但若每行仍初始化一万个格，时间成本仍要算。扩容迁移时旧数组与新数组暂时同时存在，峰值内存也应计双份。

## 图算法的输出，怎样交出可验证的证据

最短路程序除距离dist，还可以保留前驱parent。例：边S→A权2、S→B权5、A→B权1。若输出dist[B]=3、parent[B]=A、parent[A]=S，沿前驱恢复S→A→B，逐边相加为3，能证明3确实是一条可行路径的长度。再检查每条边的松弛不等式$dist[v]\le dist[u]+w(u,v)$，说明没有任何边能进一步改善。

这两类检查结合才有力度。只查不等式，给所有点写0在非负图上也可能蒙混过关；它们未必都由源点可达路径产生。只查路径，可接受长为5的S→B，虽然另一条路径长3。还要检查不可达点的无穷表示，前驱不能形成环，源点的边界也应正确。

MST类似：先查所选边连通、无环、边数为V−1，再在小图中枚举所有生成树比较最小权。只看总权巧合相同，可能接受不连通边集；只看是一棵树，又不能证明权最小。

## 性能实验要比较真实工作量

测n与2n，线性、平方、排序的理论操作量大致分别乘2、4、略多于2。实际墙钟时间还受分配、缓存、解释器启动、系统调度影响。先用操作计数确认增长，再用固定环境、相同输入副本、重复测量检验实际延迟。数据生成和打印应移出计时区，计算结果必须被使用，避免优化器把被测循环删掉。

输入形状要能逼出不同路径：BST递增插入会变长链；快排全相等可暴露错误分区；散列表大量墓碑可能让失败查询变慢；带状DP要测长度差恰好k与k+1；单调栈测严格递增与严格递减。不要把“随机数据上很快”写成最坏保证。

## 自己试做

1. 设某个lower_bound程序返回p=1，数组`[2,2,5]`、查询2。它满足下标合法，为什么仍应被拒绝？
2. 对快矩形算法，`[2,2]`结果只报面积2。怎样写最短的状态说明，帮助作者看出等高处理的问题？
3. AVL中序已经有序，还要检查哪些结构性质？举一项中序遍历查不到的错误。

答案：

1. p之前的下标0存2，不满足“p之前所有值严格小于2”。验证左半性质就能拒绝，不能只查`a[p]>=x`。
2. 补0时应让右边2先算宽1、面积2，再让左边2算宽2、面积4。若只留下右边2却没保存最左起点，宽度会丢失；若保持两个等高柱，必须继续结算左边那根。提交两次弹栈的`i,p,left,width`即可定位。
3. 每个节点高度差至多1、缓存height/size正确、parent与孩子互指、无环、节点数与所有权正确。例如某个孩子parent指向错误，中序递归不读parent，仍可能完全正确，后继查询却会走错。
